Deskripsi Pelaksanaan Kegiatan

Setelah seluruh hasil perancangan sistem pada tahap sebelumnya tersusun dengan baik, mahasiswa melaksanakan tahap pengembangan dan implementasi sistem CERIA secara penuh dan menyeluruh secara mandiri di Wisma Tegalsari. Kegiatan berlangsung selama 15 jam mulai pukul 22.00 WIB hingga 13.00 WIB keesokan harinya, mencakup pembangunan seluruh komponen utama aplikasi web berbasis Next.js dengan dukungan backend Supabase.

Pengembangan dimulai dari pembangunan sistem autentikasi berbasis email dan kata sandi menggunakan Supabase Auth, dilanjutkan dengan implementasi antarmuka wizard input data tiga langkah yang dirancang khusus untuk memudahkan kader posyandu berusia lanjut dalam memasukkan data hasil pemeriksaan kesehatan warga. Seluruh logika klasifikasi kesehatan otomatis berdasarkan standar WHO dan Kemenkes RI turut diimplementasikan sebagai fungsi murni yang terpisah dari antarmuka, sehingga mudah diperbarui apabila terjadi perubahan ambang batas di masa mendatang. Fitur manajemen data warga, rekap statistik tingkat desa, ekspor CSV, serta impor data dari berkas CSV juga berhasil diselesaikan dalam satu sesi pengerjaan ini.

Tantangan utama yang dihadapi selama pengembangan adalah penyeimbangan antara dua kepentingan yang secara kasat mata bertentangan: di satu sisi sistem harus tampil profesional, modern, dan kredibel sebagai produk teknologi yang dapat dibanggakan; di sisi lain antarmuka harus tetap sederhana, mudah dibaca, dan tidak membingungkan bagi kader posyandu yang mayoritas berusia lanjut dan memiliki keterbatasan literasi digital. Solusi yang diterapkan adalah penggunaan desain visual yang kaya dengan palet warna bermakna dan hierarki tipografi yang jelas, namun dengan navigasi yang sangat linear dan tidak memiliki menu tersembunyi — sehingga sistem terlihat modern tanpa mengorbankan kemudahan penggunaan. Tantangan kedua adalah kurva belajar penggunaan Supabase sebagai layanan backend untuk pertama kalinya, khususnya dalam hal konfigurasi Row Level Security dan pemahaman alur autentikasi berbasis JWT yang memerlukan penyesuaian berulang hingga sistem berjalan sebagaimana mestinya.

Seluruh komponen berhasil diintegrasikan dan diverifikasi berfungsi dengan baik pada akhir sesi, ditandai dengan keberhasilan proses build aplikasi tanpa error menggunakan perintah npm run build.

Deskripsi Pelaksanaan Kegiatan

Setelah seluruh komponen sistem CERIA berhasil diintegrasikan pada tahap sebelumnya, mahasiswa melaksanakan tahap pengujian menyeluruh dan perbaikan bug secara intensif selama 5 jam. Kegiatan ini mencakup empat area pengujian utama: pengujian unit (unit testing), pengujian lintas halaman (page testing), pengujian keamanan (security audit), serta pembersihan kode (code cleanup) dari seluruh peringatan lint (lint warnings).

Pada area pengujian unit, dijalankan 101 kasus uji otomatis mencakup seluruh logika bisnis inti aplikasi: fungsi klasifikasi kesehatan (IMT, Tekanan Darah, Gula Darah Puasa/Sewaktu, Kolesterol, Lingkar Pinggang), fungsi validasi input (NIK, tanggal lahir, jenis kelamin, rentang pengukuran), fungsi parsing CSV, fungsi format data (masking NIK, format tanggal), serta fungsi pencatatan aktivitas (activity log). Seluruh 101 kasus uji berhasil dilewati tanpa kegagalan.

Pengujian lintas halaman dilakukan dengan memverifikasi seluruh rute aplikasi (14 rute) secara manual: halaman beranda, login, lupa password, reset password, dashboard, input data, daftar warga, rekap, rekap detail per status, impor CSV, recycle bin, serta halaman 404. Diverifikasi pula bahwa seluruh halaman terproteksi (dashboard, input, daftar, rekap, import, recycle bin) berhasil mengarahkan pengguna yang belum login ke halaman login, termasuk rute /rekap yang sebelumnya belum terproteksi.

Pada area pengujian keamanan, dilakukan audit terhadap penyimpanan kredensial pengguna. Ditemukan bahwa fitur "Ingat saya" pada halaman login menyimpan kata sandi dalam format plaintext di localStorage browser — suatu kerentanan keamanan serius yang berpotensi dieksploitasi oleh pihak yang memiliki akses fisik ke perangkat. Perbaikan segera dilakukan dengan mengubah perilaku fitur tersebut sehingga hanya menyimpan alamat email, bukan kata sandi, sehingga pengguna tetap perlu memasukkan ulang kata sandi setiap kali login. Selain itu, diperiksa pula konfigurasi file .env.local yang memuat kunci rahasia Supabase, dan dipastikan bahwa file tersebut tidak pernah tercommit ke repository GitHub berkat pengaturan .gitignore yang benar.

Pada area pembersihan kode, diperbaiki seluruh 13 error lint dan 19 peringatan lint yang ditemukan, termasuk penghapusan variabel dan fungsi yang tidak terpakai, perbaikan pola penggunaan React hooks (setState di dalam useEffect), serta penambahan konfigurasi eslint yang sesuai. Hasil akhir berupa 0 error lint dan hanya 2 peringatan yang bersifat disengaja (unused variable untuk fitur tooltip masa depan dan dependency array yang sengaja dikecualikan untuk mencegah infinite loop).

Deskripsi Pelaksanaan Kegiatan

Setelah seluruh pengujian pada tahap sebelumnya dinyatakan lulus, mahasiswa melaksanakan deployment sistem CERIA ke lingkungan produksi selama 4 jam. Deployment dilakukan pada dua platform utama: Vercel sebagai layanan hosting aplikasi web dan Supabase sebagai layanan database serta autentikasi, keduanya menggunakan paket layanan gratis (free tier) sehingga seluruh pengelolaan sistem dapat berjalan tanpa biaya operasional.

Langkah pertama yang dilakukan adalah finalisasi konfigurasi lingkungan produksi (environment variables) pada dashboard Vercel, memastikan seluruh variabel lingkungan yang diperlukan — termasuk URL proyek Supabase dan kunci API publik — terkonfigurasi dengan benar dan terpisah dari source code. Konfigurasi ini krusial karena aplikasi tidak akan berfungsi tanpa koneksi ke backend Supabase. Selanjutnya, dilakukan verifikasi seluruh migrasi database (migration) yang diperlukan, termasuk migrasi penambahan kolom jenis_gula_darah dan migrasi perbaikan kebijakan Row Level Security pada tabel pemeriksaan untuk memastikan operasi restore data dari recycle bin berjalan tanpa hambatan.

Deployment ke Vercel bersifat otomatis — setiap push ke branch utama repository GitHub akan memicu proses build dan deploy secara otomatis oleh Vercel. Namun, pada tahap ini dilakukan verifikasi manual bahwa proses deployment berjalan lancar dan aplikasi dapat diakses melalui URL produksi https://ceria-puskesmas.vercel.app. Dilakukan pula pengujian ringan pasca-deployment untuk memastikan seluruh fitur utama berfungsi di lingkungan produksi: login, input data, pencarian data, serta tampilan rekap statistik.

Tantangan yang dihadapi selama deployment terutama berkaitan dengan konfigurasi middleware pada framework Next.js versi 16 yang memiliki perubahan perilaku dibandingkan versi sebelumnya. Teridentifikasi pula adanya file vercel.json yang berisi konfigurasi rewrite yang mengarahkan seluruh URL ke halaman utama, sehingga menghalangi penanganan halaman 404 oleh Next.js. Konfigurasi tersebut segera dihapus agar mekanisme not-found handling bawaan Next.js dapat berfungsi sebagaimana mestinya. Selain itu, route /rekap yang sebelumnya tidak termasuk dalam daftar protected routes pada middleware berhasil ditambahkan sehingga halaman rekap statistik juga memerlukan autentikasi sebelum diakses.
